# StockPilot v1.0 갭 분석 & 개선 로드맵

- 문서 버전: `1.0`
- 대상: `stockpilot_agent_brief.md v1.0`, `stockpilot_data_spec.md v1.0`
- 목적: 현재 스펙의 공백을 식별하고 v1.x / v2.0 개선 우선순위를 제시

## 0. 우선순위 매트릭스

| 우선순위 | 영역 | 대표 공백 | 이유 |
|---|---|---|---|
| `P0` | 백테스트 프로토콜 | 과거 검증 규격 부재 | 알파 증명 불가 |
| `P0` | 리스크 관리 계층 | MDD·포지션 사이징 미정의 | 점수만 있고 매매 규칙 없음 |
| `P0` | 파라미터 레지스트리 | 매직 넘버 산재 | 튜닝·재현성 불가 |
| `P1` | 기업행위 처리 | `adj_close` vs `close` 정책 부재 | 장기 계산 왜곡 |
| `P1` | 골든 테스트 | 레퍼런스 입출력 없음 | 회귀 테스트 불가 |
| `P1` | 앵커 이벤트 카탈로그 | VWAP 앵커 선정 모호 | 지표 재현성 하락 |
| `P2` | 레짐 감지 | 모든 장세에 동일 수식 | 과잉적합 위험 |
| `P2` | KR 네이티브 매크로 | VIX만으로 KR 리스크 부족 | 현지 민감도 약함 |
| `P2` | 관측성 | 운영 단계 미정의 | 장애·드리프트 탐지 어려움 |

## 1. 스코어링 로직 공백

### 1.1 파라미터 레지스트리

최소 22개의 매직 넘버가 하드코딩돼 있음.

예시:

- `120`: MA 기간
- `30`: VIX 임계
- `-0.5`: 금리차 임계
- `63`: RS 비교 창
- `2`: Ichimoku/HA 승수
- `7.5`: POC/VWAP 접근성 기본값
- `80`, `50`, `0.2`: Stoch 커브

권고:

- `config/params.yaml`로 전량 이동
- 수식 문서는 숫자 리터럴 대신 파라미터 이름을 참조

### 1.2 RS 비교 창 미명시

`rs_vs_kospi`의 lookback window가 문서화되어야 함.

권고 기본값:

- `63거래일`

### 1.3 Ichimoku 두께 미반영

현재는 `Cloud_Top`만 사용.

잠재 개선:

- `|span_a - span_b|`를 지지력 프록시로 추가 검토

### 1.4 하드 컷 경계

연속성 문제:

- `vix_close < 30`
- `stoch_k_14 < 80`
- `keltner_break > 0 AND vol_ratio > 1`

향후:

- 연속 감쇠 함수 검토 가능
- 단 해석 가능성과 트레이드오프 존재

### 1.5 음수 모멘텀 페널티 부재

`MAX(0, ...)` 구조 때문에 나쁜 상태와 보통 상태가 모두 `0점`으로 뭉침.

향후:

- `raw_score`를 병기해 랭킹 해상도 확보

### 1.6 다이버전스 앵커 선정 모호

결정 필요:

- `argrelextrema(order=?)`
- confirmation lag
- 저점이 3개 이상일 때 어떤 쌍을 택하는가

### 1.7 POC 시간 단위

`일봉 근사`와 `분봉 프로파일`의 정밀도 차이가 큼.

권고:

- 운영 시 일관성 우선
- 스펙에 근사/정밀 모드를 분리 기재

## 2. 데이터 아키텍처 공백

### 2.1 `adj_close` 정책

장기 시계열 팩터는 `adj_close`, 당일 돌파 판정은 `close`를 써야 함.

필수 조치:

- 스키마에 `adj_close` 명시
- 지표별 사용 필드 매트릭스 문서화

### 2.2 거래일 캘린더

반일 거래, 휴장, 세션 타입이 `volume_ma_20` 같은 지표를 왜곡할 수 있음.

### 2.3 생존 편향

상폐/합병 이력이 없어 백테스트가 과대평가될 위험이 큼.

필수 조치:

- `delisted_date`, `delisted_reason`, `merged_into_ticker`

### 2.4 앵커 이벤트 카탈로그

`vwap_anchored`의 앵커 선정 우선순위가 필요.

권고:

- 개별 종목: `earnings > volume_spike > gap_up`
- ETF/지수: `fomc > cpi > quarter_start`

### 2.5 시간대 조인 규칙

KR/US 시장과 US 매크로의 날짜 비대칭을 표 형태로 문서화해야 함.

### 2.6 FX 테이블 부재

혼합 포트폴리오의 다운스트림 포지션 사이징에는 `fx_daily`가 필요.

## 3. 백테스트 프로토콜 공백

현재 가장 큰 공백.

필수 최소 사양:

- 기간: 최소 10년
- 유니버스: 상폐 포함, as-of 멤버십
- 분할: Train / Validation / OOS / Live paper
- 거래 비용 모델 명시
- 성과지표 세트 명시
- 통계적 유의성 검정 포함

필수 산출물:

- `summary.pdf`
- `equity_curve.parquet`
- `trades.parquet`
- `factor_attribution.parquet`
- `parameter_sensitivity.json`

## 4. 리스크 관리 공백

### 4.1 포지션 사이징

권고 기본:

```text
weight_i ∝ (score_i / Σscore) × (target_vol / realized_vol_i)
```

### 4.2 드로우다운 룰

권고:

- `-5%`: 경고
- `-10%`: 신규 편입 중단
- `-15%`: 50% 축소
- `-20%`: 전량 청산

### 4.3 집중 한도

- 단일 종목 `20%`
- 단일 섹터 `35%`
- 상위 5개 `60%`
- 상관 > `0.7` 쌍 합 `20%`

### 4.4 종목별 스톱

- 하드 스톱 `-10%`
- 트레일링 스톱 `-15%`
- 시간 스톱 `60거래일`

### 4.5 킬 스위치

권고 트리거:

- `MACRO_HALT`
- `UNIVERSE_STRESS`
- `DATA_QUALITY_HALT`
- `EXECUTION_STRESS`
- `DRAWDOWN_KILL`

## 5. 운영 & 관측성

필수 SLO:

- 스코어링 성공률 `>= 98%`
- p95 계산 지연 `< 5분`
- DQ 플래그 비율 `< 5%`
- 점수 분포 KL divergence `< 0.3`
- Filter 통과율 드리프트 `±15%p`

필수 대시보드:

- 일별 점수 히스토그램
- Filter 통과율
- Stage 2/3/4 평균 추이
- DQ 원인 리더보드
- 상/하위 종목 리더보드
- 누적 수익률 비교

## 6. 거버넌스 & 진화

원 연구의 핵심은 `LLM 팩터 발견 루프`.

구조:

```text
텍스트 수집 -> Gemini Map-Reduce -> 후보 JSON -> 자동 백테스트 -> 승인 패널 -> 사양서 패치
```

승인 기준 예시:

- 단독 IC `> 0.03`
- 기존 팩터와 상관 `< 0.6`
- OOS Sharpe 추가 기여 `> 0.2`
- rationale 제공
